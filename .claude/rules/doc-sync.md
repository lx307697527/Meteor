# 文档同步强制规则

所有新功能或架构改动必须同步落盘到 PRD 和架构文档中，禁止仅停留在代码层面。

1. **新增功能/模块**：必须在 `docs/product/PRD.md` 中补充完整的功能描述、交互逻辑、文字线框原型稿，并更新版本修订记录
2. **架构变更**（新增组件/数据模型/配置项/工具模块）：必须在 `docs/architecture/Architecture.md` 中补充技术设计说明、接口规范、变更对照表
3. **提交代码前自检**：若本次改动涉及新功能或架构变更，必须确认 PRD.md 和 Architecture.md 已同步更新，否则不得提交
4. **版本号递增**：PRD 版本修订记录中追加新行，标注版本号、修订日期、修订内容摘要

**判断标准**：如果改动会改变用户体验或系统架构图中的任何一个节点/连线，就必须更新文档。纯粹的 bugfix 或代码重构（不改变外部行为）无需更新文档。

**测试同步**：新增核心逻辑函数（VAD 参数、文本后处理、热词匹配、上屏逻辑）时，同步编写单元测试，不得留到后续批次。

5. **Wiki Digest 同步**：当 PRD.md / Architecture.md / DevOrchestration.md 发生版本号递增或新增章节时，必须同步更新对应的 `.claude/wiki/*-digest.md`，更新 Version 和 Synced 日期。
