# Bug 追踪规则

## 强制流程

修复 Bug 后**必须**同步执行以下操作：

1. **更新 `docs/qa/BugList.md`**：按模板新增一条记录，填写根因、修复方式、关联规则、关联提交
2. **根因必须写 Why**：不是"变量为空导致崩溃"，而是"录音回调中未处理设备断开事件，导致 buffer 引用失效"
3. **关联规则提取**：若根因不在现有规则覆盖范围，草拟新规则到 `.claude/rules/draft-{topic}.md`（遵循全局自进化元规则）
4. **关联提交**：填写修复该 Bug 的 commit hash

## 判定标准

| 情况 | 是否需要记录 |
|------|-------------|
| 功能 Bug（影响用户体验） | 必须记录 |
| 代码逻辑错误（未暴露给用户） | 必须记录 |
| 性能问题（不达标但可运行） | 必须记录 |
| 配置/环境问题（非代码缺陷） | 视情况记录 |
| 拼写错误/格式问题 | 不需要 |

## 优先级定义

| 优先级 | 含义 | 修复时限 |
|--------|------|---------|
| P0 | 核心链路不可用（无法录音/无法上屏/崩溃） | 立即修复 |
| P1 | 功能异常但有 workaround | 当次迭代内 |
| P2 | 体验瑕疵，不影响核心功能 | 排期修复 |

## 与自进化元规则的衔接

- Bug 根因若出现 2 次 → 草拟规则到 `.claude/rules/draft-{topic}.md`
- 草拟规则预防 3+ 次问题 → 正式写入 `.claude/rules/{topic}.md`
- 详见全局 `CLAUDE.md` 自进化元规则章节
